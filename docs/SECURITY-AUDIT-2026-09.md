# Extended security review — 2026-09-17

This is a source review with regression tests and dependency/container scanning, not a certification or a promise of zero vulnerabilities. The untouched upstream-derived baseline remains on `main`; changes are reviewed in PR #1. Deployment on the owner's actual VPS has not been inspected.

## Changes from the first hardening pass

| Area | Finding and mitigation | Regression evidence |
|---|---|---|
| Nezha compatibility | gRPC state/GeoIP calls checked only credential presence; unknown nodes were auto-created and short IDs could panic. Require an administrator-provisioned UUID and matching nonempty token for every handler, refresh stream credentials, remove automatic creation and cap message/stream sizes. | Wrong/missing/rotated credential, short-ID and unauthorized-registration tests; valid telemetry remains accepted. |
| Live dashboard | Existing connections cached login and visibility. Refresh permissions and hidden-node state for every reply; recheck private-site access for MJPEG frames. | Real WebSocket test hides a node, revokes admin login and enables private mode on already-open connections. |
| Agent authority | Basic-info maps could modify administrator-owned columns. Accept only documented hardware, OS, IP and version fields; derive UUID from authenticated identity and region on the server. | `TestBasicInfoCannotModifyAdminFields` checks credential, name, visibility, price and identity preservation while accepting CPU telemetry. |
| Session lifetime | Expired sessions could be used by account-binding lookup; password recovery did not revoke existing sessions. Enforce expiry and account existence, revoke sessions transactionally on recovery/deletion. | Session audit tests cover expiry and password recovery. |
| Persistent RPC | WebSocket principal was established only at connection time. Revalidate credentials for every message. Limit HTTP batches to 100 calls. | Real WebSocket test revokes a session and rejects the next administrator call; registry test checks guest/agent denial of administrator methods. |
| Remote terminal | Session lookup lacked agent-node binding, connection state was unsynchronized, empty input could panic, and established sessions outlived revoked credentials. Bind agent identity, synchronize lifecycle, limit writes, recheck both credentials before forwarding and every five seconds. | Wrong-agent claim rejection; real paired WebSockets exercise empty input and revoked-user input rejection. |
| Agent WebSockets | A connected agent could continue reporting after token rotation. Revalidate its token before processing each message. | Covered by source review and existing reporting tests; idle connections need not close immediately. |
| Two-factor settings | An enabled TOTP seed could be replaced through the enable flow. Reject re-enrollment in both handler and conditional database update. Apply a bounded 10 attempts/user/5 minutes verifier limit to all callers. | Enabled-seed preservation test; password-login limiter tests remain in place. |
| OAuth | QQ callback skipped cookie/query state equality; GitHub states did not expire. Require matching state for every provider, expire/delete state, secure temporary cookies, bound external response size/time and put GitHub client secret in form body. Disabled OAuth rejects callbacks. | Source review and existing login tests. Real GitHub/QQ/generic provider round trips require configured provider credentials and are not verified here. QQ aggregators must preserve the state query in the supplied callback URL. |
| Browser request security | Cross-site navigation could omit Origin. Reject cross-site Fetch Metadata requests by default, retaining explicitly allowed origins, API-key requests/preflight and the state-validated OAuth callback. | CORS tests include cross-site GET without Origin. Older clients without Fetch Metadata still rely on Origin and SameSite protections. |
| Download SSRF | Preflight DNS checks did not bind the actual network connection or redirect. Validate addresses within the dialer, connect to that exact address, repeat on redirects, disable environment proxies for theme downloads, restrict schemes and bound size/time. | Local/private/reserved-address rejection tests and a loopback server that must not be reached. This policy applies to theme downloads, not administrator-configured notification endpoints. |
| ZIP import | Unbounded expanded content and unsafe archive entries could exhaust disk or escape extraction. Validate all entries, reject duplicate paths/symlinks/special files and use rooted filesystem operations. | Traversal, duplicate, expanded-size, symlink and normal extraction tests. Existing-destination symlink test requires OS support. |
| Frontend parsing | Data-size parser evaluated input using `Function`. Replace with numeric/scientific notation and multiplication parsing (at most 32 factors). | Frontend compile/build plus targeted parser checks. General JavaScript expressions are intentionally unsupported. |
| Secrets and headers | SQL tracing could expose interpolated credentials, and concurrent key initialization could replace a key. Redact SQL/error text and serialize in-process key creation. Add API no-store, nosniff and no-referrer headers. | SQL trace secret-redaction and response-header tests. Multiple server processes must not initialize the same data directory concurrently. |

## Scope and limitations

Reviewed the route/middleware authentication boundary, registered RPC access checks, credential storage and session lifecycle, agent report identity, terminal handoff/forwarding, OAuth state handling, theme/backup ingestion, theme network downloads, frontend dynamic execution, Docker build definitions and dependency manifests. This was risk-directed review; it does not establish that every possible execution path, race or denial-of-service condition is safe. No external-host exploitation was performed.

Archive limits are 10,000 entries and 2 GiB expanded content; theme downloads are limited to 64 MiB and theme metadata to 1 MiB. Authenticated upload request limits remain 512 MiB. Oversized legitimate backups need a separate administrator-controlled restore procedure. Theme replacement and whole-directory backup restore are not atomic transactions; take an offline copy of the data directory before either operation and before upgrading.

Full administrator access intentionally permits remote commands, terminal use, notifications to configured endpoints and installation of browser-executable themes/custom HTML. Treat administrator/API credentials and theme sources as trusted. A root agent can execute commands as root; use `--disable-web-ssh` if terminal access is unnecessary. OAuth is a separate login method: local password TOTP does not add a second challenge to OAuth; require MFA at the identity provider or disable OAuth. API keys are bearer administrator credentials and must remain private.

Use HTTPS. The reverse proxy must overwrite forwarded scheme headers, block direct public access to the backend and apply connection/request limits. Host OS, firewall, TLS termination, public exposure, existing secrets and backup permissions require deployment-specific verification. Process-local rate limits are not shared between replicas. An attacker controlling an allowed origin or administrator session remains within the trust boundary.

## Verification records

Local full server `go test ./...` passed on Windows with Go 1.26.8 and SQLite enabled; follow-up tests exercise real WebSocket forwarding/revocation. Docker's `tested` build target reruns the full server suite on Linux. The Docker workflow builds and starts the server and agent on AMD64 and ARM64, checks login/embedded UI/persistence/password migration and scans the resulting AMD64 images with Trivy 0.73.0. **Only a completed workflow result establishes that a particular commit passed.** Image reports include unfixed findings; the summary is informational and must be reviewed, not interpreted as an automatic clean bill of health.

Prior dependency scan results and upstream comparison are in [SECURITY-REVIEW.md](SECURITY-REVIEW.md). Current source/container scan findings and final run links are recorded in the PR. Static dependency presence does not by itself prove an exploitable call path, and a zero count does not cover unknown vulnerabilities. Keep monitoring security advisories and deliberately rebuild tested images; permanently freezing vulnerable dependencies is incompatible with long-term security.

## Container follow-up

The first extended image scan found 8 server findings: one unused OpenPGP module advisory in Komari and seven findings in the bundled official cloudflared binary (three high, three medium, one unknown). The agent image had zero findings. The official latest release was still 2026.9.1, so Docker now builds that exact source with locked patched dependencies; see `third_party/cloudflared/README.md`. Final image scans must confirm the resulting status. No blanket ignore list is used.

Runtime images move from Alpine 3.21 (main support ends 2026-11-01) to Alpine 3.24 (main support through 2028-06-01), per https://alpinelinux.org/releases/. This extends the maintenance window but still requires deliberate patch rebuilds.

Nezha compatibility now requires creating the node in Komari first, then configuring its UUID and token in the compatible agent. Existing empty-token auto-created records cannot authenticate; replace their credentials through the administrator UI. Its optional gRPC listener uses plaintext transport: keep it disabled unless needed, or put it behind TLS/VPN/firewall restrictions. The default Compose file does not publish that listener. This finding concerns Komari's compatibility implementation, not a claim about a particular Nezha upstream CVE.
